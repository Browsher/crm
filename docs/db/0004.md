# 0004 — habilitar RLS

**O que cria.** `ALTER TABLE usuario ENABLE ROW LEVEL SECURITY`. Nada mais.

**Por quê.** Migração própria, antes de qualquer política. Política criada
sobre tabela sem RLS é aceita pelo banco e fica inerte, sem erro: todo mundo
lê tudo. Separar em arquivo próprio torna a ordem visível e revisável.

Estado intermediário (RLS sem política) nega tudo para `app_usuario`, e isso
é correto.

Sem `FORCE`. O dono precisa ignorar RLS para as funções `SECURITY DEFINER` da
0002 não entrarem em recursão. O runner confere que nenhuma tabela tem
`relforcerowsecurity`.

**Depende de.** 0001 (`usuario`).
