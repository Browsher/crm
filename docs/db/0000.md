# 0000 — papéis

**O que cria.** `app_usuario` (`NOLOGIN`) e `app_conexao` (`NOLOGIN`,
`NOBYPASSRLS`, `NOSUPERUSER`, `NOCREATEDB`, `NOCREATEROLE`). `app_conexao`
herda `app_usuario`. `app_usuario` ganha `USAGE` em `public`.

**Por quê.** `app_conexao` é o papel da `DATABASE_URL`; `app_usuario` é quem
recebe os GRANTs e o alvo do `set_config('role', ...)` dentro de
`comoUsuario`. Os dois já entram agora porque a fatia de login precisa dessa
fronteira: `app_conexao` alcançará `autenticacao`, `app_usuario` não.
Introduzir depois seria reescrever `comoUsuario` e revisar todo GRANT.

Criação idempotente (`EXCEPTION WHEN duplicate_object`) porque papel é global
no cluster: dois bancos de teste no mesmo servidor compartilham o papel.

`NOLOGIN` de propósito: senha não entra em migração num repositório público.
`npm run db:senha -- app_conexao <senha>` dá `LOGIN` e senha por ambiente.

Nomes nossos, não `authenticated`/`anon` do Supabase. O checador barra
referência a papel de fornecedor.

**Depende de.** Nada.
