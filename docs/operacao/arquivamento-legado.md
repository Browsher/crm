# Arquivamento das duas bases antigas

Esta operação retira duas listas e 43 empresas do trabalho ativo, preservando histórico. Exige autorização operacional posterior à PR. Não carregar URLs de banco por `.env`: fornecer `DATABASE_URL_ADMIN` apenas no ambiente do comando. Os CLIs não alteram automações ou serviços.

O operador precisa ser proprietário do banco. A aplicação não tem permissão para executar a simulação administrativa nem a aplicação. Usar somente os IDs exatos do levantamento privado, sem copiar dados para fontes, issues ou logs públicos. Os caminhos de saída devem estar ignorados pelo Git dentro do projeto, em diretório operacional privado já criado; arquivos existentes nunca são sobrescritos pela simulação.

1. Com a migração publicada e autorização específica, simular com `npx tsx scripts/empresas/arquivar-legado.mts --simular --grupos <uuid1>,<uuid2> --manifesto .superpowers/sdd/<operacao>/manifesto.json --backup .superpowers/sdd/<operacao>/backup.json`. O comando exige duas listas, 43 empresas, nenhuma lista vazia, nenhum arquivo parcial e nenhuma origem compartilhada fora do conjunto.
2. Conferir privadamente as duas listas, IDs, integrantes, históricos, venda, negociação e pendências do manifesto. A simulação grava o snapshot recuperável antes de qualquer escrita comercial e mostra apenas contagens e assinatura. Guardar ambos os arquivos com acesso restrito; o backup contém dados pessoais. Em Windows, preservar também a ACL privada da pasta, pois `mode: 0600` não substitui ACL.
3. Aplicar com os mesmos caminhos: `npx tsx scripts/empresas/arquivar-legado.mts --aplicar --manifesto .superpowers/sdd/<operacao>/manifesto.json --backup .superpowers/sdd/<operacao>/backup.json --confirmar-sha <assinatura-exata-da-simulacao>`. A assinatura digitada, o manifesto e o conteúdo do backup precisam coincidir. O banco trava e refaz a fotografia antes de escrever. Nova atividade, membro, origem ou metadado invalida a aplicação; reconciliar e gerar novos arquivos.
4. Conferir arquivo gerencial, zero atividade/agenda/pendências ativas para os IDs e preservação das linhas de contatos, vendas e resultados de buscas. Repetir o mesmo comando é idempotente e não restaura nada.

Para ensaio sintético local somente, `--ensaio-local` permite quantidades menores. O modo exige host local e é recusado para host remoto. As integrações executam esse fluxo em banco descartável, incluindo adulteração do backup e confirmação errada.

O backup JSON contém os registros anteriores necessários para recuperar as linhas alteradas: `grupo_importacao.ativo`, campos/auditoria/versão de `empresa_vinculo`, `empresa_vinculo_pendencia` e `negociacao`, além de empresas, membros, contatos, vendas e origens para conferência. Os registros comerciais originais permanecem no banco, e a operação guarda o manifesto e a soma do backup. Recuperação exige procedimento separado e revisado, em banco isolado primeiro, usando UUIDs e snapshots originais para reconstituir os campos e conferir referências. Não há comando de restauração comercial automática nesta entrega.

## Ensaio de recuperação dos campos

O procedimento verificável está em [arquivamento-legado-recuperacao.sql](arquivamento-legado-recuperacao.sql), executado diretamente pelo teste [arquivo-recuperacao.test.ts](../../tests/integracao/arquivo-recuperacao.test.ts). Ele é exclusivo de laboratório: exige host local, banco descartável `teste_<12 hex>`, nome diferente do banco registrado no manifesto e nenhuma outra conexão. Não adiciona função ao banco nem modo de restauração à aplicação.

1. Fazer uma cópia isolada do banco já arquivado, conservando empresas, contatos, vendas, autores, marcadores e `arquivo_legado_operacao`. No ensaio sintético, `CREATE DATABASE <novo_nome_temporario> TEMPLATE <banco_sintetico_origem>` copia os registros sem reexecutar gatilhos. Os dois nomes são gerados pelo harness, nunca provenientes de dados de clientes. Nenhum servidor da aplicação usa o clone.
2. Ler os bytes UTF-8 do `backup.json` original, sem reformatar. Abrir uma conexão proprietária ao clone e iniciar `BEGIN`. Criar `CREATE TEMP TABLE recuperacao_arquivo(backup jsonb NOT NULL,conteudo text NOT NULL) ON COMMIT DROP`. Inserir com parâmetros independentes: `INSERT INTO recuperacao_arquivo(backup,conteudo) VALUES($1::jsonb,$2::text)`, passando o mesmo conteúdo original para ambos. Não reutilizar um único parâmetro com casts diferentes: a inferência JSONB normalizaria o texto e perderia a soma dos bytes originais.
3. Executar o SQL documental na mesma transação. Ele verifica a identidade do clone e o SHA-256 dos bytes contra a operação clonada, toma o gate e locks exclusivos e suspende nominalmente apenas oito gatilhos: guardas de arquivo e auditoria dos grupos/vínculos/pendências, mais guarda e atualização de versão da negociação. FKs, CHECKs e validação da agenda permanecem ligados.
4. O SQL recupera somente os campos que o arquivamento modifica, incluindo auditoria e versão. Grupos recebem `ativo/atualizado_em/atualizado_por`; negociações, `encerrada_em/encerramento`; pendências, `resolvida_por_arquivo_em/atualizado_em/atualizado_por`; vínculos, `agenda_contato_id/versao/atualizado_em/atualizado_por`. Vínculos são recuperados por último para conservar a versão original. Todas as chaves vêm dos records tipados do backup; não há DELETE/TRUNCATE nem atualização de contatos, vendas ou usuários.
5. Reabilitar os oito gatilhos, conferir cada registro integralmente contra os arrays originais do manifesto e conferir contatos/vendas/autores sem diferenças. Exigir zero gatilhos de aplicação desabilitados e provar que uma nova alteração comercial de empresa arquivada continua sendo recusada. Só então fazer `COMMIT`; qualquer divergência exige `ROLLBACK`, que também desfaz os `DISABLE TRIGGER` transacionais.
6. Conservar marcadores e operação como evidência nesse ensaio e remover o clone descartável pelo harness. O laboratório prova recuperação de valores e metadados; não reativa empresas na aplicação. Uma eventual restauração comercial requer decisão e procedimento próprios, pois remover o marcador e liberar trabalho ativo não está autorizado nesta entrega.

Validação em 30/10/2026: o teste focado criou backup pelo CLI, arquivou a origem, clonou-a para outro banco temporário e executou o SQL acima. Grupo, vínculo, agenda, negociação e pendência recuperaram os registros originais integralmente; contatos, vendas, valores e usuários/autores permaneceram iguais. Todos os gatilhos foram reabilitados e a proteção do arquivo continuou recusando escrita. Os dois bancos sintéticos foram removidos ao final.
