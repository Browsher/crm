# Fatia `app_teste` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O harness de teste passa a usar papel próprio (`app_teste`), que herda os privilégios do `app_conexao`, para que rodar a suíte pare de derrubar a `DATABASE_URL` do ambiente de dev.

**Architecture:** Uma migração cria `app_teste` `NOLOGIN` e sem senha, membro de `app_conexao` com `WITH INHERIT TRUE` — o piso de privilégios vem da herança, medida, e não de cópia. O teto (nada além do que herda) e os atributos que a herança não carrega (`CONNECTION LIMIT`, `idle_in_transaction_session_timeout`) viram invariante no checador, condicional à existência do papel. O harness conecta como `app_teste` e só escreve senha se a conexão falhar, e recusa `DATABASE_URL_ADMIN` que não seja de host local.

**Tech Stack:** TypeScript, Node, `pg`, Vitest (projetos `unitario` e `integracao`), Postgres 17 em container (produção: 18.6), migrações SQL numeradas com soma conferida.

**Spec:** `docs/superpowers/specs/2026-09-10-app-teste-design.md`

**Branch:** `fatia/app-teste` (já criada; a spec está commitada nela)

## Global Constraints

- **TDD sem exceção.** Teste vermelho primeiro, rodado e visto falhar, antes de qualquer implementação. Se a implementação foi escrita antes do vermelho, desfaz e refaz.
- **Nunca commitar na `main`.** Trabalhar em `fatia/app-teste`; a integração é por PR.
- **A autoridade é do banco.** Privilégio, papel e política se conferem no catálogo (`pg_auth_members`, `pg_roles`, `pg_db_role_setting`), nunca no TypeScript.
- **R-010:** herança mora no grant. Ler `pg_auth_members.inherit_option`, **nunca** `pg_roles.rolinherit`. `ALTER ROLE ... NOINHERIT` não desliga herança existente — medido em 2026-09-10, `rolinherit` vira false, `inherit_option` fica true e o privilégio continua.
- **Senha nunca entra em arquivo versionado que roda na Railway.** A migração cria o papel `NOLOGIN` e sem senha; só o harness dá `LOGIN PASSWORD`.
- **`app_teste` não entra em `PAPEIS_APLICACAO`.** Toda invariante sobre ele é condicional à existência do papel.
- **Nome do papel literal nos testes**, sem constante intermediária: `grep app_teste` e `grep app_conexao` têm que continuar achando o que existe.
- **Migrações têm soma conferida e `eol=lf`** (já garantido por `.gitattributes`). Migração aplicada não se edita.
- **Não rodar a suíte durante verificação manual** até a Tarefa 5 estar feita — é justamente o problema que a fatia conserta.

```sql
-- ver docs/db/0021.md
BEGIN;
DO $$ BEGIN
  CREATE ROLE app_teste NOLOGIN NOBYPASSRLS NOSUPERUSER NOCREATEDB NOCREATEROLE;
EXCEPTION WHEN duplicate_object THEN NULL; END $$;
GRANT app_conexao TO app_teste WITH INHERIT TRUE;
ALTER ROLE app_teste CONNECTION LIMIT 20;
ALTER ROLE app_teste SET idle_in_transaction_session_timeout = '30s';
COMMIT;
```

Nada de `GRANT CONNECT`: o padrão do Postgres concede `CONNECT` a `PUBLIC` no banco novo. Se a Tarefa 4 falhar com `42501` ao conectar, é aqui que o `GRANT` entra — e só então.

```ts
// O harness apaga bancos e altera papéis do cluster. Papel é global, então
// rodar a suíte contra a Railway não estraga só o banco de teste: estraga o
// cluster de produção. A conferência é sobre o host da URL — o que se digita
// no .env —, e não sobre o que o Postgres enxerga: numa conexão do Windows
// para o container, o servidor vê o IP do bridge (172.18.0.1) enquanto o host
// da URL é localhost. Quem lê a URL é o cliente, e o cliente é o harness.
const LOCAIS = new Set(['localhost', '127.0.0.1', '::1'])

export class HostNaoLocal extends Error {
  constructor(host: string) {
    super(
      `a suíte só roda contra banco local — ela apaga bancos e altera papéis do cluster. ` +
        `DATABASE_URL_ADMIN aponta para ${host}.`,
    )
    this.name = 'HostNaoLocal'
  }
}

export function exigirHostLocal(url: string): void {
  let host: string
  try {
    // Medido em 2026-09-10: `hostname` devolve [::1] COM os colchetes para a
    // forma [::1] da URL. Tirar os colchetes deixa a lista com um nome só por
    // endereço.
    host = new URL(url).hostname.replace(/^\[(.*)\]$/, '$1')
  } catch {
    throw new HostNaoLocal('uma URL que não pôde ser lida')
  }
  if (!LOCAIS.has(host)) throw new HostNaoLocal(host)
}
```

// app_teste NOLOGIN e sem senha de propósito: ela roda na Railway também, e
// senha em arquivo versionado seria credencial de produção.

// Papel é global no cluster e a senha sobrevive a CREATE/DROP DATABASE: depois
// da primeira vez ninguém precisa escrever de novo. Só escreve se a conexão
// falhar — em regime são zero escritas por rodada.
let loginGarantido: Promise<void> | undefined
function garantirLoginDeAppTeste(urlServidor: string): Promise<void> {
  loginGarantido ??= (async () => {
    const u = new URL(urlServidor)
    u.username = PAPEL_TESTE
    u.password = SENHA_APP_TESTE
    const cliente = new Client({ connectionString: u.toString(), ssl: configSsl(lerEnv()) })
    try {
      await cliente.connect()
      await cliente.end()
      return
    } catch (erro) {
      // 28P01: senha errada. 28000: papel sem LOGIN (container novo, ou depois
      // de docker compose down -v). Qualquer outro erro é problema de verdade e
      // sobe: 42501 e 3D000 diriam que falta GRANT CONNECT, que a 0021 não dá
      // porque o padrão do Postgres concede CONNECT a PUBLIC.
      const codigo = (erro as { code?: string }).code
      if (codigo !== '28P01' && codigo !== '28000') throw erro

    await comAdmin(urlServidor, (c) =>
      c.query(`ALTER ROLE ${PAPEL_TESTE} LOGIN PASSWORD '${SENHA_APP_TESTE}'`),
    )
  })()
  return loginGarantido
}

## Notas para quem executa

**O que pode dar errado, e o que fazer:**

- **`ALTER ROLE` de teste que não é desfeito.** Os controles negativos da Tarefa 2 alteram um papel global. Se um `finally` falhar, o próximo arquivo roda com o limite errado e a invariante acusa. Conserto: `ALTER ROLE app_teste CONNECTION LIMIT 20`.
- **`42501` ou `3D000` ao conectar como `app_teste`.** Significa que `CONNECT` não veio por `PUBLIC` como esperado. Aí sim a `0021` ganha `GRANT CONNECT`, mas **não** por edição: a `0021` já estará aplicada e a soma é conferida — entra uma `0022`.
- **O caminho de conserto preguiçoso não tem teste automatizado**, por decisão registrada na spec: exercitá-lo exige deixar o papel sem `LOGIN` no meio da suíte, que é a escrita global que a fatia está tirando. Ele é verificado à mão, no passo 2 da verificação manual.
- **Postgres 17 no container, 18.6 em produção.** Toda medição desta fatia valeu contra 17.11. É divergência já registrada em `divida-tecnica.md`, não é dívida nova, e nada nesta fatia depende de comportamento que mude entre 17 e 18 — mas nada disso foi conferido contra 18.6.
