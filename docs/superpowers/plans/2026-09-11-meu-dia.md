# Meu dia

> **For agentic workers:** Use superpowers:subagent-driven-development.

**Goal:** entregar `/meu-dia` como rota própria, com a agenda do dia à esquerda,
perfil parado à direita e histórico sob demanda.
**Architecture:** reaproveitar `lerMinhasEmpresas` e `lerHistorico` sem SQL novo.
A página servidora entrega a agenda já classificada pelo banco; a seleção é
estado de cliente, para a rolagem da lista não reiniciar; o histórico da
selecionada vem por action, e a autorização mora numa função de servidor
testável contra banco real.
**Tech Stack:** Next16, React19, TypeScript, CSS Modules, Vitest/Playwright.
**Spec:** ../specs/2026-09-11-carteira-meu-dia-design.md (seção Meu dia).

## Restrições globais

- Sem migração, sem SQL novo, sem dependência nova, sem alterar RLS ou reserva.
- Classificação de retorno vem do banco (`situacaoRetorno`). Nenhuma comparação
  de data em TypeScript; nenhum relógio do navegador decide atraso.
- Data civil de fixture é sempre `(now() AT TIME ZONE 'America/Sao_Paulo')::date`,
  como `tests/integracao/carteira-retornos.test.ts:47` já faz. Nunca
  `CURRENT_DATE` solto, que é data do fuso da sessão do Postgres, nem literal.
- Apenas a carteira do próprio usuário. Gestor não ganha visão global.
- Não carregar histórico de toda a carteira para montar a lista.
- Nenhum histórico de um cliente aparece sob o nome de outro, nem durante
  carregamento. Pedido antigo é descartado na troca de seleção, na desmontagem
  e quando a lista esvazia.
- Sem tabela de tarefas, score, funil, botão de concluir ou reagendar.
- Sem travessões nos textos da interface. Sem inventar cargo, telefone ou dado.
- Arquivo novo em `app/` lê o vizinho que já faz aquilo (R-018). Os moldes
  estão citados em cada tarefa.
- Afirmação sobre o repositório nasce de `grep`/leitura (R-022).
- Branch `codex/meu-dia`, PR contra `main`, sem empilhar PR (R-021).
  `AGENTS.md` e `CONTINUIDADE-CODEX.md` continuam fora de commit.
- Cada comportamento novo começa por RED. Rodar o teste e ver falhar antes de
  implementar. Nenhum teste é relaxado para passar.

// app/meu-dia/historico.ts
export async function historicoDaAgenda(usuarioId: string, empresaId: string): Promise<ResultadoAgendaHistorico> {
  const minhas = await lerMinhasEmpresas(usuarioId)
  if (!minhas.ok) return { ok: false, motivo: 'falha' }
  // Empresa fora da carteira responde igual a empresa inexistente: a existência
  // dela não é informação que o vendedor deva receber. Mesma decisão do
  // notFound() de app/carteira/[id]/page.tsx.
  if (!minhas.carteira.some(e => e.id === empresaId)) return { ok: false, motivo: 'fora_da_carteira' }
  const r = await lerHistorico(usuarioId, empresaId)
  return r.ok ? { ok: true, contatos: r.contatos } : { ok: false, motivo: 'falha' }
}

- [ ] **Passo 4: implementar o carregamento sob demanda**

O estado do histórico carrega o id a que pertence, e a renderização só o usa
quando o id bate com a seleção corrente. Isso é o que garante que nota de
cliente nenhum apareça sob o nome de outro:

```tsx
type EstadoHistorico =
  | { fase: 'carregando'; empresaId: string }
  | { fase: 'pronto'; empresaId: string; contatos: Contato[] }
  | { fase: 'erro'; empresaId: string; motivo: 'fora_da_carteira' | 'falha' }

const pedido = useRef<object | null>(null)
useEffect(() => {
  if (!atual) { pedido.current = null; setHistorico(null); return }
  const meu = {}
  pedido.current = meu
  setHistorico({ fase: 'carregando', empresaId: atual.id })
  void historicoDaAgendaAcao(atual.id)
    .then(r => { if (pedido.current !== meu) return
      setHistorico(r.ok ? { fase: 'pronto', empresaId: atual.id, contatos: r.contatos }
                        : { fase: 'erro', empresaId: atual.id, motivo: r.motivo }) })
    .catch(() => { if (pedido.current !== meu) return
      setHistorico({ fase: 'erro', empresaId: atual.id, motivo: 'falha' }) })
  // Desmontagem e troca de seleção invalidam o pedido pelo mesmo caminho.
  return () => { if (pedido.current === meu) pedido.current = null }
}, [atual?.id])
```

Na renderização, `historico?.empresaId === atual?.id ? ... : 'Carregando histórico'`.

vendedor perdeu a posse e os dados anteriores não continuam na tela. Com a
lista vazia, `atual` é `undefined` e o efeito zera perfil e histórico.

## Decisões de execução

A seleção é estado de cliente, não parâmetro de URL. Com a seleção na query,
cada clique refaz a página servidora e a rolagem do contêiner volta ao topo, que
é justamente o critério de aceite da spec. O custo é que a seleção não entra no
histórico do navegador, e a spec não pede isso.

A autorização do histórico mora em `app/meu-dia/historico.ts`, separada da
action, porque `exigir` não roda fora de requisição e a regra que importa
(posse, outro vendedor, gestor, perda de posse) só se prova contra banco real.

`app/meu-dia/agenda.ts` copia o parser de `app/carteira/filtros.ts` em vez de
importar: as duas telas filtram conjuntos diferentes, e um parser comum
precisaria de opções que só existem para esconder a diferença. Se uma terceira
tela aparecer com o mesmo conjunto, aí sobe para `src/lib`.
